# flashfloppy (fork)

Notes for a Claude Code session working in this fork of FlashFloppy. The upstream is https://github.com/keirf/flashfloppy, the remote `upstream`; the owner's fork is https://github.com/mike-shevchenko/flashfloppy, the remote `origin`. This file is the owner's, not upstream's: it is tracked on the branch `private` alone, and must not get into a pull request.

## What the fork is for

A universal firmware for Gotek floppy emulators with the AT32F415 (SFRKC30.AT2, QFN32) and the AT32F435 (SFRKC30.AT4.35): the Apple2 mode becomes a mode that the firmware detects by itself, so that one firmware serves both an Agat-7 and a Shugart host such as the Pentagon or the ZX Evolution. Then the useful parts of Oleg Odintsov's firmware "307", and last the owner's own improvements (display, Agat-7 font). The plan is `private/ADR-universal-firmware.md`; the bench notes, the wiring and the history of the hardware are in `C:\Retro\comps\agat\FloppyEmu 140\gotek-agat-summary.md`.

## Branches

The model is the one of the owner's fork of bitsnpicas (`C:\github\forks\bitsnpicas\CLAUDE.md`):

- `master` only ever follows the upstream; no commit of the owner's goes there.
- One branch for each pull request. A fix to a feature is committed on the branch of that feature. A branch is stacked on another only when it needs it.
- A branch keeps a proper history: each feature is a commit of its own; only similar or inseparable changes are squashed, and a change, fix or addition to a commit of the current feature branch is folded into that commit, rewriting the branch along the way without asking, even when it is on `origin` already (the owner's word of 2026-10-06; it overrides the global rule of asking before a rebase). Each commit still builds by itself. After such a rewrite, `mine` is built anew from `master` as below.
- A branch sent to a pull request is rewritten only between review rounds, and only with a comment on the pull request that names the changes and gives the `git range-diff` summary (the owner's word of 2026-10-08, replacing "never rewritten" of 2026-10-07); while a review is under way, fixes are appended as commits instead. The upstream's own tradition: since 2021 Keir Fraser applies the commits of contributors onto `master` linearly, as their committer; before that he merged pull requests on GitHub. So a branch for a pull request stays linear on `master`, each of its commits builds by itself, and its titles and code follow the upstream: `component: Capitalized title` with no article and no period, four spaces, K&R braces, `/* */` comments, nothing of the upstream reformatted or moved, so that a rebase stays cheap.

## Flash size on the STM32F105/AT32F415

The shugart firmware for the STM32F105 and the AT32F415 is nearly full: after `apple2-mode` the prod build has about 6.8 KB of headroom, the logfile build 332 bytes and the debug build 132 bytes, and every commit that adds code must be built at all three levels on that MCU before it is kept (`quick_build.sh` in the session scratchpad did that; `make dist` fails on the first overflow). The AT32F435 has over 100 KB everywhere. Measured on 2026-10-08, per function with `arm-none-eabi-nm -S` on the logfile and debug objects:

- Every level is compiled with `-g -Os` (`Rules.mk`): there is no unoptimized build, and `-g` costs nothing in the image.
- The debug level differs from logfile by about 520 bytes in the image, in three things: `console.o`, the UART console, 84 bytes more than `logfile.o` which it replaces; `ASSERT()`, live only at the debug level (`inc/types.h`), 6 to 12 bytes per assert, some 250 bytes in all across `hfe_open()`, `img_open()`, `bc_rdata_flux()`, the DMA handlers, `floppy_insert()`, `F_call_cancellable()` and the directory sort - the debug build's actual substance; and `dump_file()` in `main.c`, which prints the whole FF.CFG to the console at startup, 88 bytes of little use since the file is on the stick. In debug builds the Apple2 phases also move from PA10/PA9 to PA6/PA15, which changes the instruction sequences around the pin constants by a few bytes.
- The log strings themselves cost the same at both levels, and nothing at prod, where `printk()` is an empty inline.
